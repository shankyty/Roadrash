# Road Rash: Rickshaw Rumble — Unreal Engine fork (vertical slice)

Date: 2026-10-02
Status: approved design, pending implementation plan

## Goal

A fork of the 3D web game (v2.9.0, `web/`) as an Unreal Engine 5 C++ project in `unreal/`. The first
milestone is a playable vertical slice of one track, **Mumbai · Marine Drive**, using native Unreal
systems: Chaos Vehicles physics, Unreal lighting and positional audio. The web game stays the reference
and keeps shipping as before; the Unreal fork is committed to the repo but not released via web/Homebrew.

## Constraints

- Engine: latest UE5 from the Epic Games Launcher (installed by the user). The UE 5.2 already on this Mac
  can't build C++ with Xcode 27 (UBT accepts Xcode 14.1–15.9 only).
- No hand-made binary assets: every `.uasset` is produced by scripts so the project rebuilds from the repo.
- Vehicle models are built in Blender 5.1 (headless) and rigged for Chaos (one bone per wheel).

## Layout

```
unreal/
  RoadRashUE.uproject            C++ project; ChaosVehicles + EnhancedInput + ProceduralMeshComponent plugins
  Source/RoadRashUE/             gameplay C++ (module RoadRashUE)
  Tools/blender/                 Blender Python: model + rig + export FBX (auto, car, bus, truck)
  Tools/editor/                  UE editor Python: import FBX, materials, input assets, build level
  Tools/audio/                   extract web audio (base64 in web/*.js) to WAV for import
  Content/                       generated by the scripts (meshes, materials, input, level, audio)
  setup.sh                       Blender export → UBT compile → headless editor import + level build
  README.md
```

`setup.sh` is idempotent: rerunning it regenerates everything under `Content/`.

## Gameplay (vertical slice)

### Track
- `ARRTrack` actor builds the road from the same track recipe as the web game: the seeded
  `mulberry32` RNG and `addRoad` curve/hill sections are ported so a seed produces the same layout.
- Road: a spline (one point per few segments) with a procedural road mesh supporting 4/6-lane stretches,
  tapers, double yellow centre line, lane dashes, kerbs, junction cross roads, stop lines, zebras.
- Roadside: buildings, palms, street lamps, signs, signals, the traffic cop — placed by the same rules as
  the web game (`buildTrack`, `placeSigns`, junction layout).
- The editor script places one `ARRTrack` in the level and bakes it (generated components saved in the
  map), so the level opens ready to play.

### Player auto
- `ARRAutoPawn` derives from `AWheeledVehiclePawn` with a `UChaosWheeledVehicleMovementComponent`,
  three wheels (front centre, rear left, rear right), light mass and a high centre of mass so hard
  cornering can tip it (crash + respawn on our side of the road).
- Cameras: helicopter (default, matches the web heli cam) and chase; **C** toggles.
- Lathi: **A/D** swing left/right — arm animation plus a hit test against rivals alongside.
- Controls via Enhanced Input assets created by script: arrows/WASD drive, A/D lathi, Space/W/S horn,
  C camera, P/Esc pause.

### Rivals
- `ARRRivalPawn`: same Chaos auto; AI steers along the track spline at a lane offset, races, avoids
  traffic, and swings the lathi when alongside the player (port of `updateRivals`).
- Knockouts from lathi hits and from cross-traffic T-bones.

### Traffic and junctions
- `ARRTrafficVehicle` (car/bus/truck, Chaos): lane-following AI porting `driveTraffic` — keep left,
  buses/trucks outermost, safe gap growing with speed, indicate before lane changes, overtake on the
  inside, merge before a lane ends, stop at red / busy junction. Oncoming traffic in its own lanes.
- `ARRJunction`: 22 s light cycle (G 11 s, A 2.5 s, R; cross green 14.5–21 s), signal lamp materials,
  cross-traffic spawning and queueing, red-jump detection and the ₹200 challan at cop junctions.
- Collisions are physical (Chaos): rear-ends, side scrapes, head-ons, T-bones. Damage from impact
  impulse feeds player health and crash.

### Race
- `ARRRaceGameMode`: grid on our side of the road, countdown, laps, standings, finish, cash, challans.
- HUD: C++-built UMG (position, time, track, KOs, speedometer, health, rival health, messages/popups).

### Audio
- Two-stroke engine loop pitched by engine RPM; real horns (truck/bus); curse and hawker voice clips;
  Marine Drive city ambience; all as positional (attenuated) sounds. Clips are extracted from the web
  game's embedded base64 audio.

### Not in this milestone
Other six tracks, menus/pause UI beyond a basic pause, sound mixer, cows and dogs, night mode, mobile
build, packaging/release.

## Testing

- Blender: headless check that each FBX has its mesh and wheel bones `wheel_f`, `wheel_rl`, `wheel_rr`
  (car/bus/truck: `wheel_fl`, `wheel_fr`, `wheel_rl`, `wheel_rr`, plus extra axles for the truck).
- C++: compiles with UnrealBuildTool (Editor and Game targets).
- Unreal Automation Tests (headless, `Automation RunTests RoadRash`), no rendering needed:
  - track generator matches the web game for the Marine Drive seed (segment count, curves, junctions);
  - lane positions, 4/6-lane layout and the light cycle;
  - traffic rule decisions (stop at red, merge before lane end, keep gap);
  - race standings and challan.
- Smoke test: headless game run of the level, the player auto driven forward for 30 s; fails on errors
  or if the auto falls below the road.

## Milestone checkpoints

1. Project compiles; editor opens a generated empty level.
2. Blender vehicles imported; the auto drives on the generated road with the heli camera.
3. Rivals race; lathi fights.
4. Traffic and junctions.
5. HUD, audio, start/finish — slice complete.
